# Function Motion

## Philosophy

Motion communicates system state.

It should not exist merely because animation is possible.

Function should feel fast.

Animations should therefore be:

- Short
- Controlled
- Subtle
- Purposeful

## Assistant Opening

When the user presses the global shortcut, the assistant should appear quickly.

The animation should communicate:

Closed
→
Available

Avoid a large dramatic entrance.

## Listening

The assistant icon can subtly respond to microphone activity.

The movement should remain restrained.

Do not create a pulsing neon orb.

## Processing

Processing should communicate that the request is being interpreted.

Use subtle motion around the assistant state.

## Acting

Tool execution can use small transitions.

Example:

Opening Chrome
→
Navigating
→
Reading
→
Complete

## Completion

Completion should have a brief visual confirmation.

Avoid celebratory animations.

Function completed a task.

It does not need fireworks.

## Error

Errors should transition clearly into an error state.

Do not use aggressive shaking animations.

## Reduced Motion

Respect operating-system reduced-motion preferences where available.

## Performance

Motion must not interfere with interaction.

Animation should remain GPU-efficient and lightweight.
